02 / The rendering journey

A frame,
made explicit.

Vulkan exposes the steps that turn geometry into pixels. This sample keeps the object simple so the machinery stays visible.

Read main.cpp ↗
01 /

Open a window & choose a GPU

GLFW creates a resizable window and Vulkan surface. The application selects a physical device with graphics and presentation queues and swapchain support, then creates a logical device.

02 /

Build the pipeline

The swapchain supplies images for presentation. A render pass, depth attachments, framebuffers, and graphics pipeline define how each image is drawn. Viewport and scissor are dynamic.

03 /

Transform & draw

A view-projection matrix is sent to the vertex shader as a push constant. One draw call emits 18 vertices: four side triangles and two triangles for the square base.

04 /

Present & repeat

Semaphores and fences coordinate image acquisition, GPU work, and presentation. The swapchain is recreated when the window changes size or the surface becomes out of date.

03 / The shader

Geometry lives
in the shader.

The vertex shader stores positions and colors in arrays indexed by gl_VertexIndex. The camera matrix transforms each vertex; the fragment shader outputs the interpolated color.

// shaders/triangle.vert layout(push_constant) uniform Transform { mat4 mvp; } transform; // Position and color arrays contain 18 entries. void main() { gl_Position = transform.mvp * vec4(positions[gl_VertexIndex], 1.0); color = colors[gl_VertexIndex]; }
04 / Run it yourself

Go native.

On Linux, install a Vulkan driver and the development dependencies, then build with CMake. CMake compiles the GLSL shaders to SPIR-V with glslangValidator.

In the native window and the preview above, drag to orbit, middle or right drag to pan, and Ctrl-click a face to select a pivot. Press O or P to switch projection, + or − to zoom, and R to reset.
